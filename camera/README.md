# camera —— K230 摄像头端

跑在 **K230D CanMV 庐山派 Lite** 上：YOLOv8 检测乒乓球 → 把球心坐标通过串口发给 STM32；
另外可选地联网 —— RTSP 推流给后端、并接收后端下发的遥控指令。

## 硬件 / 固件

| | |
|---|---|
| 板子 | 庐山派 K230D Lite（`k230d_canmv_lushanpi_lite`） |
| 固件 | CanMV v1.8-6-g60b6b51 |
| 传感器 | gc2093（1920×1080@30） |
| 屏幕 | LCD 800×480 |
| 模型 | `best.kmodel` —— YOLOv8n，输入 320×320，nncase 2.11.0 |

> 模型文件体积较大，没有放进仓库。需要的话找作者要，或用你自己的数据集重新训练 + 编译。

## 文件

| 文件 | 作用 |
|---|---|
| `main.py` | 主程序：YOLO 检测 + 串口上报坐标 +（可选）RTSP 推流 / 后端 TCP |
| `test_yolo_only.py` | 只跑检测，不联网、不开串口。**排查"检测不到球"时先跑这个**，能一眼看出是模型/摄像头的问题还是别的东西在干扰 |
| `test_rtsp.py` | 单独验证 RTSP 推流链路（用 VLC 拉流看画面） |
| `test_robot_tcp.py` | 单独验证与后端的 TCP 链路（握手 / 心跳 / 收遥控指令） |

## 部署

1. 把 `main.py` 和 `best.kmodel` 拷到 **SD 卡根目录**
2. 上电自动运行 —— 板子开机会自己执行 `/sdcard/main.py`
3. 调试时也可以在 CanMV IDE 里点"运行"

## ⚙️ 跑之前必须改的配置

`main.py` 顶部这几行是**占位符**，换成你自己的：

```python
ENABLE_NET    = True          # False = 完全不联网，只跑「检测 + 串口」，最稳
WIFI_SSID     = "你的热点名"
WIFI_PASSWORD = "你的热点密码"

SERVER_IP     = "后端电脑的IP"    # 后端电脑在【同一热点】下的 IP
ROBOT_TOKEN   = "后端给的token"
```

> ⚠️ **热点密码和 token 不要提交进仓库。** 这份文件里是占位符，改完记得确认 `git status` 里没有把它们带出来。

`ENABLE_NET = False` 是个很有用的调试开关：整块联网代码会被跳过，摄像头管线完全独占，
任何网络问题都影响不到检测。**怀疑"联网把检测拖慢了"时，用它做对照实验。**

## 串口协议（K230 → STM32，115200 8N1）

物理层走 **UART1**，引脚 **IO3 = TX / IO4 = RX**。

### 接线（⚠️ 交叉接，别接成 TX 对 TX）

```
K230 IO3 (TX) ──→ STM32 PB11 (RX)
K230 IO4 (RX) ──→ STM32 PB10 (TX)
GND ──────────── GND            ← 必须共地，否则收到的全是乱码
```

### 报文

| 报文 | 含义 |
|---|---|
| `"412,238\n"` | 球框中心坐标（**显示坐标，800×480**） |
| `"Mf\n"` / `"Mb\n"` / `"Ml\n"` / `"Mr\n"` / `"Ms\n"` | 遥控：前进 / 后退 / 左转 / 右转 / 停（**只在手动模式下生效**） |
| `"MM\n"` / `"MA\n"` | 切换 **手动** / **自动** 模式 |
| （什么都不发） | 画面里没有球 |

**核心约定：自动追球模式下，K230 只说"球在哪"，不说"该往哪走"。**
丢球之后是冲、是停、是转圈找，全部由 STM32 按"多久没收到坐标"自己判断 ——
丢失判断只放在一个地方，两边各有一套时间必然打架。

## 联网（可选，`ENABLE_NET = True` 时）

### RTSP 推流

板子当 RTSP 服务端，后端（ZLMediaKit）按 hello 里上报的 IP 主动来拉：

```
rtsp://<板子IP>:8554/video
```

- 编码 H264，分辨率取 LCD 尺寸（宽对齐到 16 的倍数）
- 实现是 **WBC 回采**：抓 LCD 显示输出再编码，所以**画面里带检测框**
- **单线程**，在主循环里顺带推（不是独立线程）—— 板子上的线程会抢解释器锁，
  严重时会把 YOLO 主循环饿死。推流全部用非阻塞调用，拿不到就跳过
- 调节 `RTSP_FPS`（默认 20）可以换取更多/更少的 CPU

### 后端 TCP

连后端 `9999`（行分隔 JSON，`\n` 结尾）：

| 方向 | 报文 |
|---|---|
| 上行 | `{"t":"hello","dev":"k230-01","ver":"1.0","ip":"<本机IP>","token":"..."}` |
| 上行 | `{"t":"status","fps":25,"detected":1}`（每秒一条，兼心跳） |
| 下行 | `{"t":"move","dir":"f｜b｜l｜r｜s"}` |

收到第一条 `move` 时会自动给 STM32 发一次 `MM` 切进手动模式；
之后每条 `move` 都翻译成对应的 `M*` 指令转发给 STM32。

## 已知现象 / 排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 球在屏幕上、框也在，但车不动 | ① 串口接线（TX 对 TX）② 框宽 < `MIN_BOX_PX`(20) 被当噪点丢掉 | 核对接线；把 `DEBUG_UART = True` 打印实际发出的字节 |
| 框一闪一闪 | 置信度在阈值线上抖动 | 已把阈值降到 0.2（干扰物实测最高 0.153）。还闪说明是距离/运动模糊 |
| RTSP 画面转了 90° | 竖屏面板回采的固有现象 | 在播放端修：VLC「工具→效果和滤镜→几何→变换→旋转270度」；网页端加 CSS `transform: rotate(-90deg)` |
| 联网后 fps 明显下降 | 推流开销 | 调小 `RTSP_FPS`；或 `ENABLE_NET = False` 做对照 |

**调试串口时**：把 `DEBUG_UART` 改成 `True`，控制台每秒会打印一行实际发出的字节
（`UART out: b'412,238\n'`）。有这行 = K230 正常在发，问题在线上或 STM32 侧；
没有 = K230 压根没发（球太小被过滤，或没检测到）。
