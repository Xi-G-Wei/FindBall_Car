# controller —— STM32 主控端

摄像头找乒乓球小车的下位机代码。STM32F103C8T6 + DRV8701 驱动的四轮底盘。

**职责：收 K230 发来的球坐标，决定车往哪走。**

## 模块

| 文件 | 干什么 |
|---|---|
| `User/main.c` | **主循环 + 跟踪决策**。所有和"车该怎么走"有关的逻辑都在这里 |
| `Hardware/USART3.c/.h` | 串口收坐标。USART3，PB10(TX)/PB11(RX)，115200 8N1 |
| `Hardware/motor.c/.h` | 四轮底盘动作：前进 / 后退 / 原地转 / 边走边转的弧线 |
| `Hardware/PWM.c/.h` | TIM3 四路 PWM，给电机调速 |
| `Hardware/selftest.c/.h` | 上电自检剧本。⚠️ 跑跟踪时必须关掉，它和跟踪逻辑会抢方向盘 |
| `Hardware/OLED.c/.h` | OLED 驱动，暂时没接进主循环 |
| `System/Tick.c/.h` | 1ms 系统心跳，给所有判断提供时间基准 |
| `System/Delay.c/.h` | 阻塞延时。⚠️ 自检里才用，主循环绝对不能写 |
| `Start/` `Library/` | STM32 启动文件和标准外设库，不用改 |

## 两个设计上的点

**① 串口解析不用 `atoi()`。**
`atoi` 对乱码返回 0，看起来就像"球在 (0,0)"，车会朝一个假方向冲出去。
`USART3.c` 里是逐字符校验的，一个非法字符就整行作废。

**② 丢球之后怎么走，只由一个地方决定。**
K230 只说"球在哪"，看不见就闭嘴。是冲、是转、还是继续跟，全在 `main.c` 里按
"距离上次收到坐标过了多久"判断 —— 丢失判断不放在两块板子上各有一套。

## 编译

用 **EIDE**（VS Code 插件）+ Keil **AC5** 工具链。

1. 用 EIDE 打开这个目录
2. 装芯片支持包 **Keil.STM32F1xx_DFP 2.3.0**（仓库里没带，光 SVD 寄存器文件就有好几 M）
3. 编译，烧录接口选 **cmsis-dap**

`.pack/`、`.cmsis/`、`build/` 都是本地装或生成的，不影响源码阅读。
